# A4 特徴点と記述子

キーワード: ORB，SIFT，不変性，マッチング

## 問い

- 2枚の画像で「同じ点」を見つけるには，点の周りの何を比べればよいか (記述子)
- 回転・拡大縮小・明るさの変化に強い (不変な) 記述子は，どういう工夫でそれを実現しているか
- 誤ったマッチングはなぜ起きるか．比率テスト (ratio test) は何を見て誤りを減らしているか

## 最初の一歩

- 関数: `cv2.ORB_create`, `cv2.SIFT_create`, `detectAndCompute`, `cv2.BFMatcher`, `knnMatch`, `cv2.drawMatches`
- 最初の実験: 本の表紙を撮った画像と，カメラ映像の間で ORB の特徴点をマッチングし，`cv2.drawMatches` で表示する．
  本を回転・遠ざける・傾ける・暗くしたとき，正しいマッチングの数がどう変わるかを数える
- 次の実験: 同じことを SIFT で行い，マッチングの質と処理時間を ORB と比べる

## 他テーマとの境界

- **マッチングの仕組みの説明は A4 が担当**．D1・D3 はマッチングを道具として使う
- 第2週 07 の構造テンソル・発展課題の Harris と，特徴点の検出がどうつながっているかを説明できるとよい
- 誤ったマッチングを幾何的な整合性 (RANSAC) で取り除くのは D1 の範囲

## CPUでの注意点

- SIFT は ORB より大幅に重い．特徴点の数 (`nfeatures`) と画像サイズを変えて FPS を測り，
  リアルタイムで使える条件を示す
- 2値の記述子 (ORB) にはハミング距離 (`cv2.NORM_HAMMING`)，実数の記述子 (SIFT) には L2 距離を使う
