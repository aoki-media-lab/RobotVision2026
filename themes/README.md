# 第3・4週: CV の主要テーマの調査・実装

第1・2週では，色・差分・動きを使った処理を作り，**どんな条件で壊れるか** を観察した．
第3・4週では，班ごとに CV の主要テーマを1つ選んで原理を調べ，最小限の実装で動かし，
**うまくいく条件・うまくいかない条件** を確かめて発表する．
ここで扱ったテーマは，第5・6週のアプリ制作のコア技術になる ([project/README.md](../project/README.md))．

## テーマ間の担当の境界

複数のテーマにまたがる内容は，次のように担当を分ける．担当外の内容は「使うだけ」でよく，説明は担当の班に任せる．

| 内容 | 担当 | 使う側 |
| --- | --- | --- |
| 特徴点のマッチングの仕組み | A4 | D1・D3 はマッチングを道具として使う |
| RANSAC の原理 | D1 | D3 は使うだけでよく，平面と一般の3次元シーンの違いに集中する |
| 内部パラメータ | D2 | D3 は三角測量に D2 の結果を借りるか，近似値を使う |
| NMS の自前実装 | C2 | C1・C4 は OpenCV の NMS を使ってよい．C4 は IoU による評価に集中する |
| カルマンフィルタ | B3 | 適用先は色追跡の重心でも C5 のランドマークでもよい |

## 進め方

- 実装は第2週と同じく `from common import Trackbars, run, tile` を使い，`process(frame)` の形で書くとよい
- 生成AI の利用は認める．ただし発表の質疑では，**原理と，うまくいかない理由を自分の言葉で説明できること** を求める
- PyTorch などの GPU 前提のライブラリは使わない．実験環境のPCは CPU のみ
- 比較は **同じ録画動画** で行う (`r` で録画，`--video` で再生)．条件が違う比較は比較にならない

## 第4週の発表

各班の発表は次の構成とする．

1. **原理** (スライド1〜2枚): 手法の中心となる考え方を数式1〜2個で説明する．
   式の各記号が何を表すかを必ず書く
2. **最小デモ**: 原理を確かめるための最小限の実装を動かす．アプリにする必要はない．
   パラメータを変えると何が変わるかを見せる
3. **うまくいかない例**: 手法が失敗する例を示し，**なぜ失敗するのかを原理と結びつけて** 説明する．
   照明・遮蔽・速さ・似た物体・カメラの揺れなど，第1・2週の [観察] も参考にする
4. **応用先**: 第5・6週のアプリでどう使えるか，使うときに何に気をつけるべきか

**必須の報告事項**

- **FPS**: デモの処理速度 (画面左上の FPS と process の時間)．画像サイズなどの条件も添える
- **失敗例**: うまくいかない例を最低1つ，その場面の画像または動画とともに示す
