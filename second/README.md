## 共通部品 `common`

カメラを開き，1フレームずつ読み込み，表示し，`q` で終了する……という部分は毎回同じなので，
`common.run` にまとめてある．自分で書くのは **1枚の画像を受け取って，処理した画像を返す関数** だけ．

```python
import cv2
from common import Trackbars, run

tb = Trackbars("params", {"threshold": (120, 255)})   # 名前: (初期値, 最大値)

def process(frame):
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    _, binary = cv2.threshold(gray, tb["threshold"], 255, cv2.THRESH_BINARY)
    return binary                                     # 画像を1枚返す
    # return {"gray": gray, "binary": binary}         # 辞書で返すと複数のウィンドウに表示

if __name__ == "__main__":
    run(process)
```

- `Trackbars` はスライダーでパラメータを動かす部品．`tb["名前"]` で現在の値 (整数) が取れる．
  最小値は 0 なので，小数が欲しいときは `tb["alpha_%"] / 100` のように自分で変換する
- フレームをまたいで値を覚えておきたいとき (前のフレーム，物体の位置など) は，
  `state = {...}` のように **関数の外** に辞書を置き，`process` の中で読み書きする
- `common.tile([画像, ...], cols=3, labels=[...])` で複数の画像を1枚に並べられる (06 で使用)
- `run(process, on_key=関数)` とすると，`q r v スペース` 以外のキーを受け取れる (06 の `b` キー)
- 画面左上の **FPS** は1秒あたりに処理できたフレーム数，**process** は `process` 1回の処理時間．
  発表では必ず FPS を報告するので，見方に慣れておく

## 01 キーボードでボールを動かす

- 画像の貼り付けは numpy のスライスへの代入 `out[y0:y0+h, x0:x0+w] = fg`．
  `bg` を直接書き換えると次のフレームに前の絵が残るので，`bg.copy()` に貼る
- 幅・高さが奇数の画像でもずれないよう，左上を `cx - w // 2` とする
- 「中心座標をはみ出さない範囲に制限する」のは第1週 05 の `clamp` と同じ考え方

## 02 カメラの処理を `process(frame)` で書く

- `cv2.flip(frame, 1)` で左右反転．Webカメラの映像を鏡のように見せる
- OpenCV の描画関数 (`cv2.line`, `cv2.circle`, `cv2.rectangle`, `cv2.putText`) の座標は `(x, y)` の順で，
  **必ず int で渡す** (OpenCV 5 では float を渡すとエラー)
- `cv2.GaussianBlur` のカーネルを大きくすると処理が重くなる．FPS と process の時間を見比べる
- ここで一度 `r` を押して録画しておくと，以降の演習で同じ動画を使える

## 03 ラベリング

`cv2.connectedComponentsWithStats(mask)` は，マスクの白い画素のうち **つながっているもの** に同じ番号を振る．

| 戻り値 | 内容 |
| --- | --- |
| `n_labels` | ラベルの数 (背景を含む) |
| `labels` | 各画素のラベル番号の画像 |
| `stats` | 各ラベルの `[左上x, 左上y, 幅, 高さ, 面積]` |
| `centroids` | 各ラベルの重心 `[x, y]` |

**ラベル 0 は常に背景**．昨年度のコードは「面積が最大のラベルが背景」と仮定していたため，
物体をカメラに近づけて画面の大部分を占めると，背景を物体として扱ってしまっていた (課題1)．
「たいていうまくいく仮定」が崩れる場面を探すのも，この授業で練習したいことの1つ．

## 04 位置のなめらか化

重心はフレームごとにぶれる．過去の推定位置との重み付き平均 (指数移動平均)
`pos = alpha * 観測 + (1 - alpha) * pos` をとるとぶれは減るが，
`alpha` を小さくするほど **動きに遅れる**．ぶれと遅れはトレードオフで，
これを理論的に扱うのが調査テーマ B3 のカルマンフィルタ．

物体を見失ったフレームでは観測が無いので，前の位置を保つ (課題2)．

## 05 複数の色の追跡

色ごとの HSV の範囲を辞書で持ち，`for name, r in HSV_RANGES.items():` で回す．
HSV への変換は1フレームに1回でよい．処理の重さは FPS で確かめる．

## 06 背景差分

色を使わずに「動いているもの」を取り出す方法を4つ並べる．

| 方法 | 背景の作り方 | 得意 | 苦手 |
| --- | --- | --- | --- |
| (a) 静的背景差分 | 最初に撮った1枚 (`b` で撮り直し) | 止まっている物も検出できる | 照明の変化，カメラの移動 |
| (b) フレーム間差分 | 1つ前のフレーム | 照明のゆっくりした変化 | 物の内側が抜ける，止まると消える |
| (c) 移動平均背景 | `(1-α)·背景 + α·現在` で少しずつ更新 | ゆっくりした変化に追従 | α の選び方，止まった物が背景になる |
| (d) MOG | 画素ごとに色の分布 (混合ガウス分布) を学習 | 揺れる木の葉など背景が複数の色をとる場合 | 計算が重い，学習に時間がかかる |

- (a)〜(c) は自分で書いた `diff_mask` と `update_background` を使っている
- `uint8` 同士の引き算は負になると 256 を足した値に回り込む (課題1)．
  `cv2.absdiff(a, b)` か，`int` に変換してから引き算する
- 背景のような **フレームをまたいで学習・更新するもの** は，毎フレーム作り直してはいけない (課題3)
- `[観察]` の照明・カメラの揺れの結果は，第3週のテーマ選びや第5週のアプリ制作で
  「この手法が使える条件」を考えるときの材料になる

## 07 Lucas-Kanade 法を1点だけ解く

「点が少し動いても明るさは変わらない」と仮定し，1次の近似をとると

$$ I_x u + I_y v + I_t = 0 $$

となる．これは1点では未知数 $(u, v)$ が2つに対して式が1つなので解けない．
そこで周りの窓の全画素で同じ $(u, v)$ だと仮定し，最小二乗法で解く:

$$
\underbrace{\begin{pmatrix} \sum I_x^2 & \sum I_x I_y \\ \sum I_x I_y & \sum I_y^2 \end{pmatrix}}_{M:\ \text{構造テンソル}}
\begin{pmatrix} u \\ v \end{pmatrix}
= - \begin{pmatrix} \sum I_x I_t \\ \sum I_y I_t \end{pmatrix}
$$

- $M$ の固有値 $\lambda_1 \le \lambda_2$ を見ると，その点で動きが求まるかが分かる
  - 両方大きい → **角** (どの方向の動きも見える)
  - 片方だけ大きい → **辺** (辺に沿った動きは見えない = **開口問題**)
  - 両方小さい → **平坦** (動きが見えない)
- **Shi-Tomasi** の判定基準は「$\lambda_1$ (小さいほうの固有値) が閾値より大きい」．
  `cv2.goodFeaturesToTrack` はこの値が大きい点を選び，`cv2.cornerMinEigenVal` はこの値そのものを返す．
  自動チェックの最後で，自分の $\lambda_1$ と `cv2.cornerMinEigenVal` が定数倍で一致することを確かめている
- 1次の近似は動きが小さいときしか成り立たない．大きな動きには画像を縮小した **ピラミッド** で対応する
  (`calcOpticalFlowPyrLK` の `maxLevel`)

## 08 オプティカルフロー

- `cv2.goodFeaturesToTrack(gray, maxCorners, qualityLevel, minDistance)`: 追跡する点を選ぶ．
  `qualityLevel` は「最も良い点の $\lambda_1$ の何割以上を残すか」
- `cv2.calcOpticalFlowPyrLK(prev, next, points, None, winSize, maxLevel)`: 各点の移動先と，
  追跡に成功したか (`status`) を返す
- 追跡に失敗した点は捨てるので，放っておくと点が減り続ける．
  **点が少なくなったら，または一定フレームごとに検出し直す** (課題2)．
  点が1つも無いと `calcOpticalFlowPyrLK` は `None` を返すので，その場合も扱う (課題1)

## 09 動きの向きでボールを動かす

たくさんの点の動きを1つのベクトルにまとめる方法で，結果の安定性が大きく変わる．

- `max`: 最も大きく動いた1点 → 追跡を間違えた1点に引きずられる
- `sum`: 全点の合計 → 点の数によって大きさが変わる
- `median`: 中央値 → 一部の点が外れていても影響を受けにくい (**外れ値に頑健**)

外れ値への対処は，調査テーマ D1 の RANSAC でも中心的な考え方になる．
また，閾値の単位は [px/フレーム] なので FPS が変わると操作感も変わる．
