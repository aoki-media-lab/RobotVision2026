# 第5・6週: Webカメラを使ったアプリの制作

第3・4週で調査したテーマを活用し，Webカメラを使ったアプリを班で作って発表する．

## ルール

- **第3・4週で扱ったテーマを最低1つ，アプリのコア技術として使うこと**．
  自分の班のテーマでも，他の班のテーマでもよい．
  「コア技術」とは，それを取り除くとアプリが成り立たない技術のことを指す
- 実験環境のPC (CPU のみ) でリアルタイムに動作すること
- 生成AI の利用は認める．ただし発表の質疑では，使った技術の原理と，
  うまくいかない場面の理由を自分の言葉で説明できることを求める

## 制作の進め方

1. **課題設定**: 誰が・どんな場面で使うアプリかを決める．その場面で起こりうる条件
   (照明，背景，人数，動きの速さ，カメラの位置) を書き出す
2. **最初の版 (v0) を早く作る**: まず動くものを作り，**同じ条件で録画した動画** (カメラアプリで撮った動画を `--video` で再生) で確かめる
3. **失敗を集める**: v0 がうまくいかない場面を録画して集める．なぜ失敗するのかを，使った技術の原理と結びつけて考える
4. **改善する**: 失敗の原因に対して手を打ち，同じ録画動画で改善前後を比べる．
   「何を変えたら，何が，どれだけ良くなったか (悪くなったか)」を記録しておく

## 最終発表に含めること

- **課題設定**: どんな場面で何をするアプリか．なぜそのコア技術を選んだか (他の手法と比べた理由)
- **原理**: コア技術の原理 (第4週の発表の要点でよい．他の班のテーマを使った場合は自分たちで説明する)
- **失敗例を最低3つ**: それぞれについて，場面 (画像・動画)，原因，対処したかどうか (対処した場合はその効果) を示す
- **改善の比較**: 改善前後を同じ録画動画で比べた結果 (数値で示せるものは数値で．例: 検出できたフレームの割合，FPS)
- **FPS**: 実験環境のPCでのアプリの処理速度
- **デモ**: 実際に動かす
